# Thingelstad.xyz

Things I’ve Built: a content repository and static site for Jamie’s projects. This is a separate application from the Thingelstad.com publishing repositories.

- Use Node 24 and `npm ci`.
- `content/` is the source of truth: one Markdown file per thing, `topics.yaml`, and `history/<year>.yaml`. `data/observations/` is generated by `npm run collect` and never edited by hand. See `docs/DIRECTION.md` and `docs/HANDOFF.md`.
- Only public HTTPS URLs and public repositories enter the content tree. Keep date precision as the source states it; a first commit is development evidence, not a launch date. Observations never set a thing's status.
- `npm run site:build` builds the Eleventy site from `content/` and `data/observations/` into `_site/` (gitignored); `npm run site:serve` previews it. Templates live in `site/`, the model in `collection/site.ts`.
- `npm run format` formats source. `npm run check` runs formatting, Oxlint, Stylelint, Knip, TypeScript, unit tests, and the Eleventy build. `npm run templates` generates the CloudFormation templates into `infra/generated/` (gitignored).
- `npm run test:browser` checks the index, thing pages, topics, history, timeline, machine outputs, and the 404 page at desktop, tablet, and phone sizes against `_site/`. Install Chromium with `npx playwright install chromium` first.
- Browser tests intercept Tinylytics. Do not generate live analytics visits to verify a change.
- Never commit or publish `research/`, credentials, generated templates, or build output. Only `_site/` is public site content.
- GitHub Actions deploys validated pushes to `main` through a repository-scoped OIDC role that can only write the site bucket, invalidate the distribution, and read the site stack. Infrastructure changes require a separately reviewed CloudFormation change set applied before the code that changes the template reaches `main`; the deploy refuses to publish otherwise.
- The React application, the AI guide (Lambda and DynamoDB), and the private collection editor were retired on 2026-10-17. Edit `content/` directly.
- Follow parent AWS and secret-safety instructions. Preserve old hashed assets for open pages and rollback; the deploy never deletes objects.
