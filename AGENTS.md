# Thingelstad.xyz

Things I’ve built: a content repository and static site for Jamie’s projects. This is a separate application from the Thingelstad.com publishing repositories.

- Use Node 24 and `npm ci`.
- `collection/registry-refresh.ts` is the pure document-revision event. After byte-verified public delivery, an opted-in deploy may announce only its hash, URL and verification time, never a thing's invented publication date. Empty `SYNC_PUBLISHING_BUS` is off; failed reports leave the healthy deploy intact and the library clock as backstop.
- `sync-rebuild.yml` is the prepared bus subscriber, off: dry run is the default and uses no credentials. Real work requires `SYNC_REBUILD_ENABLED=true` and dispatches the existing collector for only the pushed repository and its commit evidence. Targeted collection PRs supersede only that repository's pending PRs. The daily clock stays until a natural event proves the replacement; never collect or publish to rehearse.
- `content/` is the source of truth: one Markdown file per thing, `topics.yaml`, `history/<year>.yaml`, and `artifacts/<id>/`. `data/observations/` is generated by `npm run collect` and never edited by hand. See `docs/DIRECTION.md` and `docs/HANDOFF.md`.
- Content is written in the first person, as Jamie (I, my, we), never “Jamie” or “he”. Quotations stay verbatim.
- Artifacts (added 2026-10-24): files from a project itself, any kind, in `content/artifacts/<id>/` and listed under the thing’s `artifacts` (file, title, caption, date, source, and a `preview` image for a file a browser cannot show). The folder must hold exactly the listed files. They are published unchanged at `/things/<id>/artifacts/<file>`; only images, PDFs, ZIP archives and text keep their content type, everything else downloads as bytes. The repository is public: read every file before adding it, and keep credentials, private data, and licensed stock art out. They enrich a thing’s page; they never revive the project. See `docs/DIRECTION.md`.
- The featured shelf (added 2026-10-24): `content/featured.yaml` lists, in order, the things the front page shows first, above the full index. It is my decision, like status, never the collector’s: at most six, each once, each active. Cards lead with the captured front page, link the title to the thing’s page and a second link to its own address. Those links carry `?ref=xyz-featured` wherever Tinylytics counts the site (any of my sites with a `tinylytics` observation, not only strip sites), so the shelf can be measured; a GitHub link stays clean. Release Notes sends Tinylytics the path only, so there the shelf shows only as the referring site. See `docs/DIRECTION.md`.
- Only public HTTPS URLs and public repositories enter the content tree. Keep date precision as the source states it; a first commit is development evidence, not a launch date. Observations never set a thing's status.
- `npm run site:build` builds the Eleventy site from `content/` and `data/observations/` into `_site/` (gitignored); `npm run site:serve` previews it. Templates live in `site/`, the model in `collection/site.ts`.
- Search (`/search/`, added 2026-10-23): after each build `collection/search-index.ts` runs Pagefind (1.5.2, the version nnxyz uses) over `things/*/index.html` only and writes `_site/pagefind/`. A thing page offers its article (`data-pagefind-body`); the crumbs, facts, screenshot, evidence, diagram, artifact images and file lines, and footer are `data-pagefind-ignore`. The page lists every thing without JavaScript; `site/js/search.js` asks Pagefind only for the words (matches, order, passages) and does the facets itself from each row's `data-filters`, so the counts always agree with the list. The facets come from the model (`facets` in `collection/site.ts`): status, the year started (every year, empty ones too, drawn as a histogram), topic, collection, and the language GitHub reports first for each repository (evidence, never a claim of the registry's). Within a facet choices widen, across facets they narrow, and a facet is counted without its own choice. The query, filters and sort live in the address; the front page's status legend links into it.
  - Two Pagefind traps. It takes the first `<img>` on a page as the result image, which here was the footer's micro.blog avatar, so “avatars” matched every page: the empty `data-pagefind-meta="image:"` in `thing.njk` stops that. And when no word starts with the whole query it shortens the query until one does (“podcasting” finds podcast, but “avatars” finds every “a”): `related()` in `search.js` keeps a match only when a marked word starts with a query word or is most of one.
  - Pagefind's index files (`.pf_meta`, `.pf_index`, `.pf_fragment`, `.pf_filter`) are named by their content and published immutable with `assets/`; its scripts, wasm and entry file keep their names and are `no-cache` (`scripts/publish-plan.mjs`). The deploy refuses a build without `search/index.html` and `pagefind/pagefind.js`.
- Activity (`/activity/`, `activity.xml`, and a thing page’s Activity section; added 2026-10-23, Jamie: “collected daily, with agent attribution shown”): `collection/activity.ts` builds it from `data/observations/commits/` (`collection/adapters/git.ts`) and `publications/` (`observePublications` in `collection/adapters/web.ts`). Who made a commit: a bot (`[bot]`, “bot” as a word, libraryupgrader) is left out; an agent when the author or a `Co-authored-by` line names Claude or Codex (anthropic.com, openai.com); me as Jamie Thingelstad or jthingelstad; an agent, unnamed, for any other `@thingelstad.com` author (Otto Thing, the Elixir team); others otherwise. Codex seldom signs, so much of its work counts as mine; the page says so. The charts follow the dataviz skill: `--who-me`, `--who-agent`, `--who-others` were validated as a set on `--paper`, the aqua is under 3:1 so every chart has its numbers as text and a legend, segments are separated by 2px gaps, and tooltips are SVG `<title>`s. The two logs are written one entry per line (`logJson` in `collection/observations.ts`) and Prettier leaves them alone. The collect workflow runs daily and asks the Internet Archive on Mondays only (`npm run collect -- --no-wayback`).
- Every page opens with the sites strip that all of Jamie’s sites share (`site/_includes/sites-strip.njk`, `collection/sites-strip.ts`). Its markup and values are a contract in `thingelstad.com/AGENTS.md` (“The sites strip”); change it there first. Every site reads as its `strip_label`, this one included, and every link carries `?ref=sites-strip-xyz` for Tinylytics. Its list is `data/sites.json`, a byte-for-byte copy of `thingelstad.com/shared/sites.json`: refresh it with `npm run sites:sync`, never by hand. `npm run sites:check` fails when the copy drifts, and checks only the committed copy where the sibling checkout is absent, as in CI.
- Shared type: the site is set in the type all of Jamie’s sites share (`thingelstad.com/AGENTS.md`, “Shared type and colour”), moved onto it on 2026-10-22 after Weekly Thing, Another Thing and Thingy. `site/css/shared/` (`tokens.css` and `fonts/`) is a byte-for-byte copy of thingelstad.com `shared/tokens.css` and `shared/fonts/`, vendored with `data/sites.json` by `npm run sites:sync` and never edited here; `npm run sites:check` fails on a stale, missing or leftover file. The build publishes the directory whole under `/assets/shared-<hash>/`, the hash over every file (`collection/shared-type.ts`), because `tokens.css` names its fonts relative to itself. `layout.njk` preloads the two latin woff2 files and links `tokens.css` before `site.css`; no font is loaded from another host.
  - Faces by role in `site.css`: `--font-heading` (Inter Tight at `--weight-heading`, 800, with `--jt-tracking-heading`), `--font-body`, `--font-ui` and `--font-label` (Inter), `--font-code` (the system mono). Never name a face in `site.css`; only the sites strip does, because its values are the contract. Diagram labels follow `--font-ui`.
  - Sizes are the blog’s scale: body `--jt-size-base` (19px, 18px on phones), headings `--jt-size-h1`/`-h2`/`-h3`, nav `--jt-size-ui` (15px below 440px and `--jt-size-label` below 390px, where the six links would not otherwise fit on one row; they never wrap, and scroll sideways only below 350px), footer, crumbs and counts `--jt-size-small`, dates `--jt-size-meta`, chips and tags `--jt-size-label` (14px). Nothing is below 14px; `tests/shared-type.test.ts` and the browser test fail on a smaller size.
  - The frame is `--jt-frame` (1120px) with `--jt-gutter` inside it, so the strip, header, main column and footer share one left edge; reading text (lede, introduction, story, screenshot) keeps to `--jt-measure` (720px).
  - No italics in the design (Jamie, 2026-10-22: “I really dislike italics with san serif fonts … I like the color and I like using font weight with san serif”). Emphasis is the green or ink, and weight: the front page’s green “built” is a 600-weight span, a thing’s introduction is muted 500. Markdown emphasis in a thing’s story is Jamie’s text and keeps its italic. `font-synthesis: none` stays, so nothing is faked bold or slanted. The tests fail on `font-style: italic` outside `em`/`i`/`cite` in `.story`, and on `<em>`, `<i>` or `<cite>` in a template.
- Dark mode (added 2026-10-23, Jamie: “give thingelstad.xyz dark mode support”) follows the reader's system setting through `prefers-color-scheme`; there is no switch. `site.css` redefines the paper palette, the status colours, `--accent-text` (the shared `--jt-xyz-text`, #74d3a0) and the small tokens (`--underline`, `--field`, `--shadow`, the sticker lightnesses, `--story-mix`) in one `@media (prefers-color-scheme: dark)` block after `:root`; templates never name a colour. Fills stay (the green mark keeps white on #1d7348). The who hues were re-validated on the dark paper and `--who-agent` steps down to #e8652f there. The sites strip takes the contract's dark values at the end of `site.css`. A browser test pins the dark paper, ink and strip.
- The same `data/sites.json` names Jamie on every page (`collection/sites.ts`): the footer carries the shared h-card (`owner`, the bird photo at 24px) and every `<head>` a `<link rel="me">` per `owner.rel_me`, as `thingelstad.com/AGENTS.md` (“Jamie on every site”) sets out. Identity links stay clean. A template link to another strip site goes through the `ref` filter, which adds `?ref=xyz-<placement>` (`thing` for a thing's own site, `source` for sources and citations, `activity` for a post listed under Activity) after any query and before any fragment. Story text is content and keeps its links; feeds, `things.json`, `llms*.txt` and the Markdown twins keep the record's URLs.
- Microformats (added 2026-10-25, the open-web audit's G17 and G18): a thing page is one h-entry (`thing.njk`: p-name, a `<data class="u-url">` of the canonical address, p-author, p-summary, the story as e-content), and every list of things (the front page's featured shelf and each collection, a topic, search) is an h-feed named by its heading, of h-entries (`thing-row.njk`, `feature-card.njk`). Every entry's p-author is the `owner` h-card from `data/sites.json`, a hidden link with the clean identity URL (`data-pagefind-ignore` on the thing page, so search is unchanged); the footer h-card (`rel="me author"`) still names Jamie for the page. An entry has no dt-published (dropped the same day, Jamie: “thingelstad.xyz drops dt-published and adds p-author”): a thing's dates are when it started and ended, not when its page was published, so the visible `<time>`s carry no class. Nothing else on a page is a microformat, and nothing nests but the author: no class may start `h-` unless it is meant as a root or is that p-author. The browser tests fail on any other root, a nested entry or feed, an entry without that author or with a dt-* date, or an entry whose properties differ from `things.json`.
- `llms.txt` (`llmsText` in `collection/site.ts`) keeps the shape the llmstxt.org reference parser reads: the title, the `>` summary and any prose come before the first `##`, and under each heading every line is `- [name](url): notes`, one link, with no bracket in the name, because one line there without a link fails the whole parse. `tests/llms-shape.ts` is the guard, run by the unit tests on `llmsText` and the browser tests on the built file.
- `npm run format` formats source. `npm run check` runs the sites check, formatting, Oxlint, Stylelint, Knip, TypeScript, unit tests, and the Eleventy build. `npm run templates` generates the CloudFormation templates into `infra/generated/` (gitignored).
- `npm run test:browser` checks the sites strip, the index, thing pages, topics, history, timeline, activity, search (with and without JavaScript), machine outputs, and the 404 page at desktop, tablet, and phone sizes against `_site/`. Install Chromium with `npx playwright install chromium` first.
- Browser tests intercept Tinylytics. Do not generate live analytics visits to verify a change.
- Never commit or publish `research/`, credentials, generated templates, or build output. Only `_site/` is public site content.
- GitHub Actions deploys validated pushes to `main` through a repository-scoped OIDC role that can only write the site bucket, invalidate the distribution, and read the site stack. Infrastructure changes require a separately reviewed CloudFormation change set applied before the code that changes the template reaches `main`; the deploy refuses to publish otherwise.
- The React application, the AI guide (Lambda and DynamoDB), and the private collection editor were retired on 2026-10-17. Edit `content/` directly.
- Follow parent AWS and secret-safety instructions. Preserve old hashed assets for open pages and rollback; the deploy never deletes objects.
